# git-release-helper

## When to use
Use this skill when: Automates GitHub release preparation, changelog extraction, and semantic version tagging when releasing software.

## Operational Runbook Workflow

### Phase 1: Pre-Flight Verification
1. Verify system environment, network access, and necessary permissions.
2. Confirm current service health and establish a baseline state.
3. Notify stakeholders and verify maintenance window parameters.

### Phase 2: Procedure Execution
1. Clarify expected inputs and outputs.
2. Inspect available files without modifying them.
3. Plan and execute the core task logic.
4. Verify the output and report any limitations.

### Phase 3: Post-Execution Verification
1. Execute health-check smoke tests to verify service availability.
2. Monitor latency, error rates, and resource utilization for 5 minutes.
3. Document completion time, operator ID, and operational metrics.

### Phase 4: Emergency Rollback Procedure
If any critical check fails during Phase 2 or 3:
1. Halt execution immediately.
2. Revert configuration or deployment using established rollback commands.
3. Verify baseline service recovery.
4. Escalate incident to designated on-call lead.

## Safety & Controls
- Never bypass pre-flight or post-execution verification steps.
- Require explicit operator approval before initiating state-changing or destructive steps.
- Maintain an audit trail of all commands and outcomes.
